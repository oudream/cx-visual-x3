## 0. 给当前开发聊天 / Codex 的执行指令（可直接复制）

我们继续实现 **CxVisual TestCenter**。请先读取主仓 `AGENTS.md`、工程 Skill、`DOCS/00`，再检查本文件、`Tests/README.md`、现有 TestCenter V4.1、`Tests/TestCenter/MainWindow.xaml(.cs)`、`UI/`、`Cases/`、AvalonDock 布局及当前 `master` HEAD。

**任务是基于现有 WPF/.NET Framework 4.8 TestCenter 做真实的增量主界面，不是再画一套概念大屏。** 请优先落实以下已确定规则：

1. **视觉**：以 `DOCS/Architecture/TestCenter/01_TestCenter_测试主界面_2560x1440.png` 及本次对话最后确认的浅色参考图为准；白/浅灰/极浅蓝、细边框、留白充分、低对比、不臃肿。杜绝大面积深蓝、粗阴影、大卡片密集堆砌。
2. **顶部**：**删除/收敛原大图标 Ribbon 按钮区域**，不再保留一整条大操作带。可保留紧凑的标题、菜单、工作区文档 Tab、面包屑/状态。测试操作按钮**全部集中右侧操作中心**；不要在顶部再复制运行/停止/发送/导出命令。
3. **四区**：左“测试项目树”、中“当前根页/子页的工作内容”、右“操作中心”、下“日志/结果/诊断/Trace/性能/资源”可停靠标签页。沿用已有 AvalonDock，不写第二套停靠系统。
4. **左树四个根**：`专有测试（人工操作）`、`自动测试（NUnit/TCT）`、`场景案例`、`结果报告`。**四根平级，遵守相同缩进、展开和选中规则，各用自己的图标与独立总界面**；其子项经统一工作区注册/真实数据投影打开页面。
5. **根页与子页**：点击根节点文字打开其**独立总界面**，点击展开箭头只展开/收起；点击子项打开对应内容。**自动测试统一复用 AutoTest 工作界面**，Foundation/Mechanism/Professional/Case 仅变筛选范围与选中用例，专业证据按需打开只读 Viewer。**四根各 1 张根页 + 1 张子页，另补专有测试 3 张专业子页，共 11 张设计。**
6. **人工操作与自动验证分离**：通道收发、规约编解码、画图、CT 三维是用户手动执行的**可操作**专有界面，不是已有 `ITCTTestViewer` 只读结果页；结果/日志可复用公共展示组件，但不能把操作事实直接变成 `Passed`。
7. **真正注册而非假树**：左树节点从注册描述符/既有 NUnit/TCT Catalog/场景目录/报告索引组合呈现，不维护第二套业务工程树。注册和打开要支持唯一 ID、父子、懒加载、实例策略、切换、关闭/释放和错误诊断。
8. **真实实施**：先核对现状，再分轮开发，编译与 Windows WPF/UIAutomation 验证后给出同 SHA 证据；没实现/没测过的写“未验证”，不凭图宣称交付。不增加 `csproj`，不改既有 F/M/P Owner 和 TestCenter 唯一 Catalog/Worker/Run/Attempt。
9. **首轮纵向切片**：先做新 Shell（四区+紧凑顶部）→ 四根注册树及根页 → “专有测试”根页 + “通道测试”子页的最小真实可操作闭环。改动范围外的高级工具先列需求，不用假页面冒充完成。
10. **交付**：提交中文 Commit，提供真实运行截图、代码差异、正常/反例、同 SHA Windows CI 及未验收清单；出现合理的 Owner 或数据合同缺口，主动指出，不能私自发明平行实现。

## 2. 项目树：四个根及建议子节点

~~~text
测试项目
├── 专有测试（人工操作）               ← 分类根 Frame / Root Page
│   ├── 通道测试                         ← 可操作 ChannelTestFrame（TCP/UDP/...为工具模式/子选项）
│   ├── 规约测试                         ← 可操作 ProtocolTestFrame（Modbus/自定义...）
│   ├── 图元绘制测试                     ← 可操作 GraphicsTestFrame
│   └── CT/3D测试                        ← 可操作 CT3DTestFrame
├── 自动测试（NUnit/TCT）                ← 分类根 Frame / 自动化工作区首页
│   ├── Foundation                       ← 分组/容器（Catalog结果）
│   │   └── GeometrySmoke（举例）        ← Catalog中真实存在时显示；否则用真实Case代替
│   ├── Mechanism                        ← 分组/容器
│   └── Professional                     ← 分组/容器
├── 场景案例                             ← 分类根 Frame / 场景目录
│   ├── X-Ray检测线                      ← 场景定义/执行/观察，真实 Owner 先核验
│   ├── CT重建流程
│   └── 设备通信集成
└── 结果报告                             ← 分类根 Frame / 报告索引
    ├── 自动测试报告                     ← TestCenter 真 Run/Attempt
    ├── 人工测试报告                     ← 人工证据（非自动 Passed）
    ├── 场景验证报告
    └── 历史与差异分析
~~~

- **根节点**：有可打开的总览页面（RootPage），不是仅展开/折叠的 Folder。
- **中间分组节点**：可作为树分组；若无明确工作内容，点击只展开或显示不冒充运行数据的分组概览，**不强制每层都有独立 Frame 类型**。
- **子叶节点**：可打开具体 Frame / 文档 Tab；同一注册项可按 `SingleInstance / PerSession / MultiInstance` 决定实例策略。
- **自动测试子叶来源**：真实 `TCTTestCatalog` 的 Category/Aspect/Group/Case；不要人为硬编码一个根下 500 个虚构自动测试，更不要把 NUnit case 注册为 500 个 WPF 类。
- **报告叶来源**：报告类型是可注册的入口；报告内容来自真实持久结果索引，不新建结果仓库。
- **空态**：未注册、无可用数据、无法创建或缺能力时准确显示“不支持 / 未发现 / 无证据 / 加载失败”，不编假状态。

### 2.1 四根与子节点的统一规则（补充定案）

| 平级根节点 | 专用图标 / 根总界面 | 子项打开原则 |
|---|---|---|
| 专有测试（人工操作） | 专业工具图标 / 专有测试总览 | Channel、Protocol、Graphics、CT3D 各自专用操作 Frame |
| 自动测试（NUnit/TCT） | 自动测试图标 / 自动测试总览 | **统一 AutoTestFrame**，按 Catalog 的 F/M/P/分组/Case 上下文切换内容；专业结果 Viewer 仅扩展观察 |
| 场景案例 | 场景图标 / 场景总览 | 按真实业务场景打开专用场景页面 |
| 结果报告 | 报告图标 / 报告总览 | 统一报告管理，按类型/Run/历史切换详情，必要时扩展 Viewer |

四根**层级、缩进、图标尺寸、展开箭头、选中高亮一致**，但各有不同 `IconKey` 和 Root Frame。所有层级都可继续展开；箭头控制展开，节点文字控制打开/选中。**树节点 ≠ Frame 类**：多个树项可注册/投影到同一个 Frame，通过 Context/Scope 更新视图与右侧操作中心；不要一用例一 WPF Frame。

## 3. Frame 注册与打开模型（建议设计，非已存在的类）

### 3.1 “工作区Frame”语义

这里的 **Workspace Frame 是 CxVisual TestCenter 的逻辑工作区/页面提供者概念**，不是强制采用 WPF 控件 `System.Windows.Controls.Frame`，也不等价于现有 `TCTTestViewBase`。

推荐最小描述符字段：

| 字段/接口（候选） | 用途及验证 |
|---|---|
| `WorkspaceId` | 唯一、稳定；同 ID 重复注册必须报错，不静默覆盖 |
| `ParentId`、`NodeKind` | Root/Group/Leaf 与树关系；缺失父节点、环、重复 ID 明确拒绝 |
| `DisplayName`、`IconKey`、`SortOrder`、`Category` | 仅导航元数据，可配置/搜索 |
| `FrameKind`、`Factory` | 创建已有 WPF 根页、人工操作页或报告页；无可用 Factory 则置 Unsupported |
| `OpenPolicy` | 单例打开/每会话打开/显式多开（须资源隔离） |
| `Context/Capabilities/Owner` | 参数、可见命令、必要授权与生产 Owner 能力 |
| `CanActivate`、`Activate/Deactivate/Close` | 激活、关闭与异步清理的职责协议，需审查真实框架后命名 |
| `Dirty/CloseGuard` | 未保存人工草稿、连接中动作与退出时的提示/拒绝 |

**注册来源建议**：启动时登记**四根、人工工具、报告页面类型**；自动测试从既有 Catalog 动态投影 F/M/P/Group/Case 树项，全部复用统一 AutoTest Frame，按 Scope/Case 传入上下文，不重复注册测试执行器；场景从已批准的目录/配置加载。树仅做投影，**不是另一个 MEM 工程真源**。

### 3.2 打开算法的契约

~~~text
Registry注册（稳定ID、Parent、Factory、能力、打开策略）
     ↓ 校验重复ID/无父节点/环/必要能力
Tree投影 + 搜索/分组
     ↓ 双击 / Enter / 根页单击
WorkspaceManager.Open(WorkspaceId, Context)
     ↓ 验证可用性 / 授权 / 同实例策略
DocumentHost增加或激活AvalonDock文档Tab
     ↓ 绑定右侧OperationCenter到“当前活动Frame”
操作命令 → Frame命令/Controller → 真正生产Owner或TCT执行合同
     ↓
界面只读观察 / 日志 / 证据，关闭时释放资源
~~~

候选命名 `Registry`、`WorkspaceManager`、`OperationCenter` 只是**逻辑职责描述**；编码前优先查现有 `TCTMainWindow`、`TCTTestDocumentHostControl`、`TCTTestExplorerControl`、`TCTTestRibbonController`，选择合理的落位和接口名，不要因为本文名称相似就创建新的平行测试框架。

### 3.3 Tree / Tab / 右侧操作中心之间的状态规则

1. Tree 选中 → 中间 Tab 打开/激活 → 右侧展示当前 Frame 的操作集合与状态 → 底部日志过滤到相关 Session/Run；Tab 选中也反向定位 Tree。
2. 点击根页：右侧提供**打开所选工具/创建会话/筛选/导入/报告**等根级操作；点击子页：只显示该工具的**连接、发送、应用、绘图、取消、保存证据**等能力对应的操作。
3. 操作中心不是静态按钮堆：不适用/没有权限/未连接/运行中时合理隐藏或禁用，并给出原因；执行任务时异步且禁重入。
4. 用户关闭 Tab 或切换工作区时：保留需要保留的 Session；释放应释放的订阅和资源；不能靠隐藏 UI 假装已经断开工业设备。
5. 工具未注册不生成错误内容页；重复/失败注册在诊断中明确报告；绝不将硬件模拟的成功误记为正式 `Passed`。
6. 与现有 WPF UI 的兼容由代码审查裁定；测试框架没有新生产 Owner，ManualSession 与 RunId/AttemptId 身份不互换。

## 4. 四个根页 / 子页：界面内容矩阵

### 4.1 专有测试根页（人工操作）

**中央**：标题“专有测试（人工操作）”+ 简短说明；通道/规约/图元/CT3D 以**小型入口卡片或单页表格**列出显示名称、已注册、简短功能、最近使用，不铺大量营销统计。最近人工 Session 列表（存在真实会话才显示）。

**右侧**：打开工作区、创建会话、目标环境（默认 Virtual/Replay）、会话/资源状态、手工证据保存、导出。根页不发送具体报文。

**首要子页：通道测试**：中央保留详细可操作连接参数、数据发送编辑器、TX/RX 流与 Hex/Text 表格；右侧连接/断开/发送/停止/导入、目标和权限；底部事件/超时/错误。参数可在中间编辑，**实际执行动作在右侧**，不要复制按钮。

### 4.2 自动测试根页与子页

**独立根总界面**：Catalog 分组、筛选、真实 Run 与少量可核查统计；右侧提供运行计划、重跑、取消等操作。

**统一子界面 AutoTestFrame**：点击 Foundation / Mechanism / Professional / Geometry 分组或具体 Case，**不更换测试框架或另建 WPF 页面类**，只切换 Scope/Case，展示对应列表、断言、Attempt、证据和 Diff。右侧按范围显示“运行分组 / 运行当前用例 / 取消 / 导出”等操作；专业图像/几何/运行证据按需加载既有只读 Viewer。复用 `TCTTestCatalog`、Worker、`TCTTestCaseResult`，不为每种测试写重复执行界面。

### 4.3 场景案例根页与子页

**中央根页**：场景清单及真实简介/Owner/可用状态、近期验证；没有正式场景应显示“待接入”，不能造一个已通过的 X-Ray 产线。

**右侧根页**：打开场景/选择环境/创建受控验证会话/查看历史、导出。

**子页例：X-Ray检测线**：中间按现有 MEM/MOL/MOC/MRK/MDS 的真实定义与运行观察，呈现上料→采图→AI/传统检测→判定→MES/PLC 的流程/步骤/结果；右侧提供获授权的开始/暂停/单步/停止、仿真模式、诊断及证据导出。未经授权不得在界面“按钮点击”直接驱动 X-Ray 或 PLC。

### 4.4 结果报告根页与子页

**中央根页**：报告类型导航、历史索引表、真实筛选、最近报告及统计，报告归档唯一；人工报告与自动 Run 证据清楚区分。

**右侧根页**：查询、打开、生成/导出（仅有真实数据时）、比较与报告路径/审核状态。

**子页例：自动测试报告**：真实 Run/Attempt 的 Passed/Failed/Skipped、耗时、对比、Trace/证据、报告预览；右侧生成、重跑来源用例、JSON/JUnit/PDF（仅在实际导出实现存在时启用）、导出与审批。**审签**不能自动覆盖 Golden，也不能将手工报告冒充 NUnit 通过。

## 7. 必测场景（含反证）

### 7.1 导航、注册与画面

- 四根平级、相同缩进/展开/高亮，**图标各异且各自打开总界面**；点击箭头只展开，点击文字打开；搜索/Tab 同步定位，空 Catalog 时无假子叶。
- 注册 ID 重复、父节点缺失、循环引用、工厂异常、权限缺失均有明确错误/诊断；不会导致整个 WPF Shell 崩溃，也不留下幽灵 Tab。
- 自动测试 F/M/P 分组及不同 Case **复用同一 AutoTestFrame 类**，按 Context/Scope 更新列表与断言，不能产生多个测试执行系统；专业只读 Viewer 可切换。
- 单例页重复打开复用原 Tab；多会话页按策略隔离；关闭页解除订阅/资源租约；重开不继承前一个 Session 的目标或权限。
- 动态切换根/子页时右侧**只**显示当前上下文命令，底部按 RunId/AttemptId/ManualSessionId 正确归属；没有操作上下文时显示合理空态。
- 浅色参考对照：顶部没有大按钮 Ribbon；左树/中页/右操作/下日志全部可见；文字清晰、面板不拥挤；AvalonDock 拖动/浮动/停靠、布局恢复及 125%/150% DPI 可实测。
- 兼容当前 `--ui-smoke` / `--ui-automation` 和已有 CLI，不删测试来“过关”。

### 7.2 人工通道安全

- Virtual TCP 正常连接、发送、接收；目标拒绝、超时、恶意输入、断线、快速点击连接/断开与关闭窗口均可复现且资源不泄漏。
- 未连接时禁用发送、运行中防重入，停止显示动作与实际状态不冲突；日志不伪造 RX 或 Packet。
- Real 模式无授权、未通过 Owner 安全检查时拒绝操作；“停止 UI/Worker”不是设备物理安全停止。
- 未声明 Assertion 时 ManualSession 可以保存操作与观察，但**不能自动产生 `Passed` 或覆写原有 TestCenter Run/Attempt/Golden**。

### 7.3 报告真实性

- 无历史报告时正确空态；只有有真实 Result/Manifest 时才计算汇总统计。
- 手工记录与自动 Result 类型、身份与审核机制区分；报告打开/比较不得静默选择另一成功 Run 替代失败 Run。
- 旧 SHA 的 Windows 绿灯、模拟体数据、设计图都不能当作本次代码及专业设备验收。
