# CxVisual 工程可视化体系：第一轮实际实现与验收（2026-10-19）

## 本文定位

最终目标是**软件开发者自然使用、工程编排用户在Studio真正可视化编辑、构建、运行和调试**的工业工程平台，不以固定“三次开发”作为完成判定。本轮实施是这个目标的基础闭环，**不能被误写成 Studio 的完整交付**。

依据：`DOCS/01_CxVisual_平台灵魂与架构宪法_V1.0_Review.md`，既有 MEM 工程组织 H00～H07，专题 `CxVisual_统一工程可视化与图元体系_完整架构设计_V1.0`，真实源码与 Windows CI。

## 项目归属与依赖

- `Foundation.Geometry`：二维纯值几何与算法，Point/Vector/Segment/Rect/Circle/Ellipse/Polyline/Polygon/Arc/Bezier/Path，统一 `FGETransform2D`。不使用WPF。
- `Mechanism.Core/Engineering`：原MEM工程真源、Page/Content/Group/Symbol/Element、MTC事务、类型描述、引用、保存/重开。
- `Mechanism.Core/VisualDefinitions`：`MRCShapeDefinition` 九种Shape、`MRCShapeElement`、Text/Image/SVG/Widget，`MRCVisualAppearance`（Style/State/Animation/Event），以已有 `MPMAspect`/Binding/TypeDescriptor/Serializer 为唯一持久化体系。
- `Mechanism.Visual`/ `Mechanism.Presentation.Wpf`：仍是目标消费端，画布多态绘制/编辑尚未在本轮完成，不把界面渲染说成已交付。
- `Professional.*`：真实设备语义及执行留在专业；3D独立。

## 实际开发者使用

见 `Examples/VisualAuthoring/EngineeringVisualQuickStart.cs`。

入口为 `MEMEngineering.Create`、`AddPage`、`AddGroup`、`AddShape`、`SetVisualStyle`、`SetBinding`、`SetVisualBehavior`、`AddTypedElement`、`AddSymbol/PlaceSymbol/SetOverride`，由工程自带事务/Revision/Undo/Redo/SaveAs处理，控件无WPF运行实例。

九种绘图入口统一为 `MRCShapeDefinition.Line/Rect/Circle/Ellipse/Polyline/Polygon/Arc/Bezier/Path`。真正几何保留零宽线段与路径控制点，原工程布局正宽高保持兼容。Rect、Circle等几何语义不等于ROI或工业设备。

Style是无WPF的ARGB Brush（None/Solid/LinearGradient/Resource）、Opacity、StrokeWidth、Font、ThemeKey；State/Animation/Event为版本化声明，具体运行触发、权限与呈现求值不在第一轮假实现。动态数据绑定沿用MPMBinding，UI更新不等于工程编辑事务。

复杂工业图元统一采用一份MEMSymbol + Group/Shape/Widget并由ResourceRef复用，设备控制能力由Automation等专业提供。

新增 `Tests/ArchitectureSmoke/VisualAuthoringStage1Tests.cs`，覆盖：

**以下必须继续做且不得标记为已完成：**

3. 工程用户实际拖放、路径节点编辑、图层、ROI、Symbol双实例画布操作及UI自动化。
4. MOL编排编辑/MOC构建/MRK运行/MDS调试完整同图闭环。
5. 所有完整几何库（高级裁剪、多边形复杂布尔、三维数学）与性能/工业安全压力测试。
