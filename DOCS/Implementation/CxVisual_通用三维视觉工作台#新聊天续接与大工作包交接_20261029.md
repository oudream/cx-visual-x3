## 4. 怎样以大工作包推进

每轮围绕一个完整用户作业，同时完成紧密相关的数据/算法、可操作界面、开发者API、MEM保存重开、失败路径及测试；可连续完成多个关联子功能。内部做必要小修改，面向用户交付完整工作包。一个类、一个按钮、一项文档更新均不自动构成阶段完成。

| 顺序 | 可交付工作包 | 必须让用户真实完成的作业 | 主要验收边界 |
|---|---|---|---|
| 0 | 当前基线收敛 | 最新master编译、默认回归、三维真实窗口及截图、历史工程兼容 | 所有失败可定位到SHA/job；本Owner失败修复，其他Owner失败记录因果，禁止假绿 |
| 1 | B包：交互ROI与多对象工程作业 | 真实RAW四视图定位→选ROI→Surface/Mesh局部分析→选中对应Feature/Measurement→组合显示→编辑/失效/复算→保存重开继续操作 | 复用已有2D切片ROI/物理四角和MVI多对象能力；补齐ROI到专业算法真实输入、原值映射、选中/删除依赖与保存，不重新写已有图层/多Mesh |
| 2 | 专业计量链深化 | 标定CT→可靠表面与质量→平面/球/圆柱拟合→有基准的尺寸/几何评价→可追溯报告 | 从现有离散合同演进表面质量、鲁棒/约束拟合与计量；GD&T按实际数学定义/基准合同实现，不能只给残差改名 |
| 3 | 分割与检测链 | CT→Mask/连通部件→缺陷或壁厚→空间定位→Inspection判定→批量/报告→保存复核 | Mask/ROI与原值Frame一致；异常、NaN、截断、预算、取消与零半成品发布；量值精度需独立样本 |
| 4 | CAD比较链 | 可靠标准格式CAD导入→人工/基准/自动配准→保存变换→正负偏差/超差区域→报告 | 先核实真实内核与部署依赖；缺SDK明确阻点，继续独立公共能力；不伪造SolidWorks/STEP支持 |
| 5 | 动画与统一宿主交付 | 同一Volume/Mesh/Mask/ROI/CAD/结果场景→相机/剖切/透明关键帧→保存重放/视频→Studio/嵌入/Headless复用 | 用同一MVI状态和MEM工程，不另建Timeline工程树或渲染真源；CPU/GPU预算、可取消、逐帧版本一致 |

这是执行优先顺序，未缩减26能力/90要求。每包开始只做一次针对真实源码的缺口核对，随即进入实现；没有证据的候选API必须先找Owner和依赖，不机械生成附录全类空壳。不以“已有演示”替代完整工业流程，也不因工业样本外部阻点停止其它可做部分。

1. 真实案例、正常/边界/失败操作、Headless与WPF同一生产逻辑；计量保留单位、Frame、来源/版本、ROI/参数/算法版本和质量证据。
2. Windows .NET Framework4.8 Debug/Release x64；结构/DAG；默认ArchitectureSmoke、`--volume`、受影响Imaging/Concurrency；真实WPF截图，GL修改另跑实卡，不把回退当GPU成功。
3. 来源丢失/损坏、预算、预取消/运算中取消、旧异步回填、保存冲突、编辑失效、重复加载/释放、历史Schema与Undo/Redo。
4. 少量主题集中的中文提交，直接master，及时推送。每次提交前再查HEAD和并行变更；不重置他人代码，不强推。`Output/`构建产物不要提交；固定测试样本需要明确列入Git。
5. 只更新原实施记录、原验收矩阵和R5主文状态；每项分开记录源码、编译、自动化、真实GPU及工业标准件。CI引用精确SHA和Run，失败必须读日志。
6. 未完成全目标时保留待办和下一包入口，不把完成一个工作包称为完成整个平台。每包通过后自动推进下一关联工作包，不反复询问是否继续；真正需要产品/Owner裁决或外部输入时才集中提出问题。
