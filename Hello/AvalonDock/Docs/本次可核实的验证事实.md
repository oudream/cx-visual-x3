## 风险与实施建议

1. 真实编译时如出现 5.0.1 API 兼容差异，应以此项目同 SHA 的 Windows 错误输出为准修复，不降级到 4.x 或改用 Xceed 包绕过。
2. 本例保存 UI 布局而非业务值，但若正式进入 Studio，需把 ContentId 映射到已存在 Editor/ViewModel，并由原机制管理业务对象生命周期。
3. XAML 和 ViewFactory 为独立演示，未复用主仓的真实 WPF Studio/工程逻辑；正式集成时只迁移必要 Docking 适配，不重复项目树、事件路由、MOC/MRK 状态库。
4. 不能仅凭此示例自动测试，就判定跨显示器 DPI/高强度拖动浮动窗口和原 Studio 100K 节点场景的性能。
