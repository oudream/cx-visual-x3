# CxVisual · 运行诊断体系 · 监控与调试 — 完整设计与验收（初简版）

> **版本**：V1.0（初简版 / 设计讨论稿）  
> **日期**：2026-10-20  
> **定位**：供后续细化、源码归位、验收设计使用；**不是完整规格，也不代表功能已经实现**。  
> **约束**：沿用 CxVisual 既有 Foundation / Mechanism / Professional 与现有项目布局，原则上不新增项目；保持 MEM 唯一工程真源、MOC 唯一构建桥、MRK 统一运行执行、MDS 统一运行时数据；C# 与 Studio 共用语义。  
> **证据说明**：目前仅参考对 x3 `master` 的定向代码查看和历史规格基线；“建议/待实现”不能写成已验证的源码行为。

## 1. 定位
运行诊断让开发者与工程编排用户**看见、定位、解释和复现一次执行**，但不自造执行引擎或第二份运行状态。数据源来自 MRK Trace、MDS 快照、日志/指标和 MOC SourceMap；Studio 负责交互呈现。

## 2. 核心能力
| 域 | 内容 | 主要来源 |
|---|---|---|
| 监控 | 活跃任务、队列、等待、失败、资源占用 | MRK/基础监控 |
| 追踪 | RunId、StepId、事件序列、耗时、异常原因 | MRK Trace |
| 源码/工程定位 | CompiledStepId → BlockId → Content/调用位置 | MOC SourceMap |
| 数据探针 | 输入输出、局部变量、帧/堆快照、质量标志 | MDS 受控只读视图 |
| 调试控制 | 断点、单步、观察、条件断点（安全模式） | MRK 控制；Studio 入口 |
| 性能诊断 | 耗时分布、吞吐、排队等待、热点 | MRK + 专业指标 |
| 回放 | 对历史执行按日志/快照回看，标识模拟与真实数据 | Journal + Trace + Fixture |

## 3. 从失败定位回 Studio 的例子
某 `Run-123/SN-001` 在 AI 节点报错：
1. MRK 记录 Trace：失败的 `CompiledStepId`、异常、Attempt、关联 RunId。
2. MOC `SourceMap` 查到 `ContentId + BlockId + InvocationPath`，区别共享子流程多处调用。
3. Studio 打开对应流程并高亮节点，查看输入图像引用、结果摘要及失败原因（按权限脱敏）。
4. 工程师选“仿真回放”使用固定计划和可重放数据；**回放不表示可以重放真实设备的物理副作用**。

## 4. 主 Owner 与技术衔接
- MRK：真实状态与 Trace 源；当前有 `MRKExecutionEngine` 等运行资产。
- MOC：`MOCSourceMap`、`MOCCompiledPlan.ReadTrace` 等工程来源映射；不单独写日志真源。
- MDS：只读快照、访问权限、敏感值隔离；避免大图像/CT体数据全部复制到 UI。
- Studio / Presentation.Wpf：断点与观察 UI、工程节点高亮、时间轴、探针。
- TestCenter：采集可复现失败证据，而非以单次显示绿色表示验收完成。

## 5. 两类用户的最小体验
**开发者**：指定 RunId 读取 Trace 和源映射，追踪并发问题与异常传播；定位到工程对象及代码 Provider。

**工程编排用户**：Studio 点击运行节点→查看这次 SN 输入/输出和耗时→设置安全断点/执行仿真→保存诊断报告；无需知道内部 StepId。

## 6. 验收与反证
- Trace 的每条执行步骤都能按 `SourceMap` 精确定位；共享子流程不同调用位置可区分。
- 高并发 Trace 不丢关键错误；若采样或环形缓冲导致丢失，明确给出丢失计数。
- UI 关闭后 Headless 运行可继续采集；新连接观察者不可修改生产状态。
- 断点仅在授权的 Debug/Simulation 环境生效，不得使硬件进入危险暂停态。
- 10 个 SN 压测下统计可按 RunId 分离；敏感配置/图片/大体数据按策略裁剪和脱敏。

## 7. 待细化
确定事件 Schema、指标维度、SourceMap 生命周期、断点协议、回放数据最小集合、可验证性能门槛；与运行控制和 TestCenter 的接口保持唯一来源。
