# CxVisual · 运行治理体系 · 部署与生命周期 — 完整设计与验收（初简版）

> **版本**：V1.0（初简版 / 设计讨论稿）  
> **日期**：2026-10-20  
> **定位**：供后续细化、源码归位、验收设计使用；**不是完整规格，也不代表功能已经实现**。  
> **约束**：沿用 CxVisual 既有 Foundation / Mechanism / Professional 与现有项目布局，原则上不新增项目；保持 MEM 唯一工程真源、MOC 唯一构建桥、MRK 统一运行执行、MDS 统一运行时数据；C# 与 Studio 共用语义。  
> **证据说明**：目前仅参考对 x3 `master` 的定向代码查看和历史规格基线；“建议/待实现”不能写成已验证的源码行为。

## 1. 定位
运行治理负责**让经过构建与验收的工程计划，以可审计、可授权、可回退的方式进入运行环境**；它管理目标、环境、版本、权限、部署策略与升级生命周期，不能替代 MOC 编译器或 MRK 执行器。

## 2. 一条完整交付链
```text
MEM 工程修订 → MOC 验证/编译 → 产物 + 依赖锁 + SourceMap
          → 治理校验（权限/目标/环境/完整性/策略）
          → Stage（预部署）→ Activate（激活）→ MRK/Runtime.Host 运行
          → Observe（监控）→ Rollback/Retire（回滚/退役）
```
构建成功**不等于可以上线运行**。生产切换必须明确审核门槛与兼容性。

## 3. 初版能力
| 功能 | 关键要求 |
|---|---|
| 构建产物身份 | ProjectId、Revision、PlanId、依赖与签名/校验值 |
| 目标环境 | 设备 Provider、GPU、PLC/XRay 连接、资源上限与版本能力检查 |
| 分级部署 | Dev/Simulation/Test/Production 环境与授权隔离 |
| 发布审批 | 操作人、角色、权限、审批/审计记录 |
| 阶段切换 | Stage、Activate、Rollback；切换时间和受影响实例清晰 |
| 升级兼容 | 已运行实例固定原版本；新增实例使用新激活版本 |
| 安全保护 | 凭据不写进工程明文；保护生产目标与高危设备操作 |

## 4. 业务例子
版本 V1 已在生产运行 10 个检测实例。新版本 V2 通过 CI 和仿真验收，先 Stage，在授权后 Activate。**已启动的 V1 实例原则上继续绑定 V1 固定计划**，新进入的实例使用 V2；回滚 V1 时应明确 V2 在途实例采用等待完成、受控取消或迁移策略，禁止静默替换。

## 5. Owner 与现状
建议 Owner：`CxVisual.Mechanism.Lifecycle` 管发布策略/生命周期，`CxVisual.Runtime.Host` 管承载装配，`Mechanism.Runtime` 提供激活与运行能力，`Mechanism.Orchestration` 产出可部署计划。现有 `Mechanism.Lifecycle` 项目当前主要为骨架，MRK 已发现 `MRKExecutionPublishing` 等文件；**需评审重叠并决定唯一 Owner，不复制发布状态机**。

## 6. 验收与反证
- 未通过编译、缺依赖、产物篡改、权限不足、目标不匹配时拒绝部署。
- Stage 不应自动启动真实设备；Activate 有可查询结果及审计。
- 回滚后新的运行任务使用目标版本，旧实例版本身份不会漂移。
- 无界面 Host 重启可恢复配置与已批准的激活版本；未授权 Studio 操作不能绕过治理。
- 涉及 X-Ray/运动安全的生产验收需硬件/现场条件单独签收，软件 CI 不能替代。

## 7. 待细化
先做单机目标发布和回滚闭环，再考虑多节点发布；与配置体系、权限体系、专业设备适配契约联合评审。
