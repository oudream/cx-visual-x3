## 1. 定位
运行保障提供运行级的**失败处理、超时、重试、补偿、恢复、隔离、资源清理和故障证据**。它提高软件流程可恢复性，但**不能代替设备安全回路、PLC联锁、急停或 X-Ray 硬件保护**。

## 2. 功能与策略
| 能力 | 规则 |
|---|---|
| 超时 | 规定等待/执行/整体截止时间，记录触发阶段 |
| 重试 | 可配置次数、退避、可重试错误码，必须声明幂等/副作用 |
| 异常传播 | 子流程故障到父流程的显式策略，不吞异常 |
| 补偿 | 按业务明确撤销/恢复动作，非通用数据库事务回滚 |
| 故障恢复 | Journal/Checkpoint/Resume 前重验资源和版本 |
| 资源保障 | finally 风格清理 Lease、订阅、缓冲、临时文件 |
| 隔离与熔断 | 故障任务不影响其他 SN；外部服务短期故障可阻断新调用 |

## 3. 典型故障：MES 写入超时
错误方案：MES 发送超时立即重试，导致同一个 SN 被重复提交。
正确方案：每次业务写入有稳定幂等键；先检查是否已确认，再按允许的错误类型重试；记录 Attempt、服务器 ACK、最终判定。若物理下料已完成，就不能简单“回滚”运动。

## 4. 定义/执行职责边界
- MOL：在工程中声明某节点的错误分支、补偿节点或可配置策略意图。
- MOC：校验重试策略和能力声明是否匹配（特别是副作用节点）。
- MRK：执行超时、重试、异常传播与恢复；保留原因链。
- MDS：保存本次实例数据与执行检查点的必要状态；不擅自恢复设备。
- Professional：判断设备能否安全停止、恢复或重试。

## 5. 代码承接与候选契约
参考 `MRKExecutionPolicy`、`MRKExecutionCompensation`、`MRKExecutionJournal`、`MRKResourceLeaseCoordinator`（应以实际公开 API 确认功能状态）。策略需显式表达 `Retryable / MaxAttempts / Backoff / Compensation / Deadline / IdempotencyKey`；名称为**概念建议**。

## 6. 验收
- 超时、取消、真实错误分类准确，并精确定位节点与 Attempt。
- 幂等动作在重放与重试中不重复产生外部副作用；非幂等动作被拒绝盲目重试。
- 并行的失败实例不污染其他 SN；子流程失败的传播与补偿顺序可复现。
- 恢复后固定工程修订/计划身份不变，恢复失败时禁止自动执行危险动作。
- 人为断电、断链、磁盘写失败、PLC拒绝等按仿真/实机级别逐项验收。

## 7. 待细化
建立错误码分类、幂等等级、可补偿性分类以及故障注入矩阵；将执行保障和设备安全手册分别验收。
