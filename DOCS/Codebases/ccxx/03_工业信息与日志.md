# ccxx深入分析 03：Interinfo / Log 工业信息与日志

> 固定源码基线：[26cecfb02e861ce6b821b33350493bac4793e997](https://github.com/oudream/ccxx/commit/26cecfb02e861ce6b821b33350493bac4793e997)，静态审计2026-10-14。未执行现场、压测与磁盘故障测试。CxVisual新仓Foundation/Infrastructure已有CxLogRecord、ICxLogSink、Memory/File LogSink样例；Mechanism.Runtime目前仅工程骨架。

## 1. 分层机制及处理流程

~~~
Producer（工业Channel、Runtime、算法、设备事件）
 -> CxInterinfoOut::outInfo / outLog
    -> 持锁遍历多个CxInterinfoOut_I观察者
       -> 根据Platform / Type / Source / Reason做过滤
          -> Platform_Cmd、Desktop、Net等控制台与消息输出
          -> Platform_Log
             -> CxLogRealtime：同步写文件
             -> CxLogThread：双缓冲字符串及FILE*队列
                -> CxLogManager::fileByFileName：文件名策略和跨日切换
Input: CxConsoleInterinfo -> CxInterinfoIn -> 输入订阅者/命令回调
~~~

这里Interinfo不仅是文本日志，它含工业运行输出、控制命令输入、平台分发、分类过滤等职责。不要直接压缩成只写一行文本的LogHelper。

## 2. 新CxVisual功能映射（建议；Owner待最终批准）

| 已有技术 | 新平台建议 |
|---|---|
| type/source/reason/target/tag | Foundation.Infrastructure的结构化记录、模块类别、Severity、Source/Target和CorrelationId |
| OutObserver/Filter | Mechanism.Runtime按会话订阅、实时事件流；Foundation定义技术无关Sink契约 |
| 记录到文件+LogThread | File/Memory/重要事件Sink、有界异步队列、异常降级及停止Drain |
| CxInterinfoIn | 受控诊断命令入口；任何工业写命令必须经过Runtime/Professional安全检查 |
| 周期清理旧日志 | 可配置Retention、按类别区分、磁盘容量限制、操作审计不可误删 |

现有x3 Foundation/Infrastructure有简化日志实现，后续应从**现有公开API出发增量扩展**，不要为了迁移ccxx重复建立日志基础类型；生命周期上应采用可管理实例，避免无界进程级全局单例。

## 3. 源码级风险与验证

| 编号 | 代码证据 | 结论 |
|---|---|---|
| LOG-01 高 | [cxinterinfo.cpp#L407-L466](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxinterinfo.cpp#L407-L466) | 在持有公共互斥时调用外部观察者。如果观察者再操作同锁或其他锁，存在重入/锁顺序风险；需实测及审查CxMutex具体行为。 |
| LOG-02 高 | [cxlog.cpp#L461-L507](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxlog.cpp#L461-L507) 与 [#L299-L357](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxlog.cpp#L299-L357) | 待写缓冲内保存FILE*；文件轮转会关闭此前的FILE*。需要在跨日拥塞时排查队列中遗留失效句柄的可能。此为静态潜在竞态，未确认现场故障。 |
| LOG-03 中 | [cxlog.cpp#L461-L507](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxlog.cpp#L461-L507) | 不见异步缓冲队列总量限制。需针对持续高日志速率+磁盘慢/满测试占用、丢弃策略。 |
| LOG-04 中 | [cxlog.cpp#L439-L457](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxlog.cpp#L439-L457) | 无数据时工作线程Sleep(15)；逐条刷新日志涉及写放大。吞吐/延迟依机器、磁盘实测。 |

风险适用于本次审查commit中对应代码；现场历史版本和调用方式需要单独核对。

## 4. 测试与交付门禁

1. 同时输出Debug/Warning/Error/Critical、一般日志/重要事件，按模块、来源、时间、工程revision检索。
2. 10000条/秒峰值下观察队列容量、内存、P99延迟与丢弃报告；验证磁盘满、文件无法创建、日志跨日、应用崩溃后恢复。
3. 动态Add/RemoveObserver、Observer抛异常/递归写日志、关停最后一条日志Flush、并发与锁顺序。
4. 对照旧LogDisables样例（all、type、source、reason）重建新系统过滤真值表。
5. 旧代码不因本档案审计而自动修改；CxVisual接入需各写正常/异常回归日志并记录真实命令与结果。
