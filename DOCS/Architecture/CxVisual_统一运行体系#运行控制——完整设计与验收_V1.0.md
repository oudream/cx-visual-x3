## 1. 定位
运行控制管理**运行实例是否、何时以及以什么可观察状态继续执行**；不定义业务流程，不直接代替 PLC、运动控制卡或设备的安全停止接口。

## 2. 控制命令与生效语义
| 命令 | 预期作用 | 必须说明 |
|---|---|---|
| Start | 从 Ready 启动实例 | 绑定固定计划和权限 |
| Pause | 请求在协作安全点暂停 | 不保证正在执行的节点立即停住 |
| Resume | 从 Paused 恢复 | 重验上下文/租约/权限与目标状态 |
| Cancel | 取消等待及可取消步骤 | 结果是 Canceled 还是 Failed 须按契约区分 |
| Step | 调试环境仅推进一个允许的逻辑步 | 不允许偷偷切换生产设备到单步模式 |
| Stop/Abort | 平台层终止推进或转为故障处理 | 不代表设备物理急停已完成 |

**状态机示例**：`Created → Ready → Running ↔ Paused → Succeeded/Failed/Canceled`。同时需要 `PauseRequested/CancelRequested/Waiting` 等中间状态与幂等规则；这是运行**实例**的状态机，与 MOL 定义的业务状态机是两个不同对象。

## 3. 工作契约
- 控制接口采用 `RunId` + 控制命令 + 请求者 + 期望版本/状态，返回 `Accepted/Rejected/Applied` 等可观察反馈；接受不等于已经生效。
- 每个节点/专业 Provider 明确 `CanPause/CanCancel/CooperativePoint` 能力；不可中断的 X-Ray 采图或运动阶段不得被 MRK 假设可瞬停。
- 状态转换必须持久记录因果信息，重试命令可幂等，非法状态操作应拒绝并解释。
- 暂停与资源释放是两个策略：某些节点可释放 GPU 工作槽，某些设备会话必须保持且限时。

## 4. 真实场景
检测线正在执行 `运动到位→采图→AI`。工程师点击“暂停”：MRK 记录暂停请求；运动任务由设备 Provider 完成安全阶段或明确返回不支持；到达可暂停点后变 `Paused`。点击“恢复”才继续 AI。若安全联锁触发，设备安全机制独立响应，MRK 记录故障/停止后果，而不是承担硬实时保护。

## 5. 项目归位与源码衔接
主 Owner：`CxVisual.Mechanism.Runtime`；优先复用现有 `MRKExecutionControls`、`MRKExecutionEngine`、`MRKRuntimeSession`，不得由 Studio 再写控制状态机。Studio 只发布命令和展示回执。专业 Provider 实现其可控性声明及安全停机契约。

## 6. 验收与反证
- Running 暂停→安全点 Paused→恢复→完成；命令状态和执行状态严格区分。
- 连续两次 Pause/Cancel 不重复执行副作用；终态不可重新 Resume。
- Pause 与 Cancel、完成事件并发到达，状态最终唯一且 Trace 完整。
- 无法协作暂停的硬件步骤必须说明原因及处理策略；断线/取消后不可误报“设备已安全停止”。
- 运行用户权限不足、实例版本不匹配、错误 RunId 统一拒绝并可追踪。

## 7. 待细化
