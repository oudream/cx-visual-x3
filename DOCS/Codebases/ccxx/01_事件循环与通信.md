## 1. 三层设计与真实事件流

```text
CxChannelTcpclient/Tcpserver/Udp/Serial
  -> 后台接收/连接线程（socket或serial）
  -> CxChannelBase::threadEventNotify(channel,event,tag,data,len,source)
       -> 如“数据事件 + _isProcessQueue”：_processer->push()（独立处理线程）
       -> 否则 CxApplication::pushProcessCallBack(processThreadNofity,...)
                   + CxApplication::signalMainThread()
  -> CxApplication::runProcessCallBacks() （普通模式下在应用事件循环处理）
  -> CxChannelBase::processThreadNofity()
  -> CxChannelBase::processReceivedData() 或 processConnect/processError/processSentData()
  -> CxChannelPublisher::receivedData/connectChanged()
  -> CxIChannelSubject 业务观察者
```

**必须保留的区别**：README描述“后台接收后转主线程”；代码还提供`_isProcessQueue`、`_isSendQueue`两个开关，所以**不能保证每一种配置下的观察者回调都在主线程**。业务开发必须显式标记调用线程和串行化语义。

## 2. Timer实现及延迟语义

- [`cxtimer.cpp#L22-L35`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxtimer.cpp#L22-L35) 固定`CxTimerHost[100]`，**100是不同interval的Host上限**，不是只能注册100个Timer对象；同interval可共享Host。
- [`cxtimer.cpp#L231-L254`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxtimer.cpp#L231-L254) 更新线程检查到期，把`fn_processTimers`通过`bOnlyOnePending=true`放入应用回调队列。
- [`cxtimer.cpp#L256-L290`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxtimer.cpp#L256-L290) 更新线程每次`sleep(10)`毫秒，再调度至应用线程；**这是软件定时处理，不是硬实时或严格10ms精度保证**。
- [`cxtimer.cpp#L398-L502`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxtimer.cpp#L398-L502) 在非应用线程启动/停止对象Timer时，通过`fn_modifyTimer`提交；Stop使用同步轮询等待Host脱离。必须实测退出过程、超时行为。
- [`cxchannel.cpp#L300-L327`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxchannel.cpp#L300-L327)：每个通道构造时创建1000ms检查Timer，用于自动开连及状态维护。

## 3. 与CxVisual的目标边界（建议，未批准）

| 能力 | 唯一Owner建议 | 可复用对象/机制 | 接口设计底线 |
|---|---|---|---|
| Socket与原始字节传输 | `Foundation.Transport` (F17) | `CxSocket`、Buffer的Native实现 | 地址族、timeout、关闭、缓冲归属 |
| 工业通信通道抽象 | `Mechanism.Connectivity` (M13-M15) | `CxChannelBase`、Road、Factory、Subject、4种通道 | Open/Close/Send/Observe/Health与Lifecycle；厂商SDK归专业Driver |
| 事件分发及运行循环 | `Mechanism.Runtime` (M26-M34) | `CxApplication`、`CxTimerManager` | Headless，支持有界队列、取消、异常结果和持续监测，不依赖WPF |
| 脚本/规则业务回调 | `Mechanism.Logic`、`Professional.Automation` | 观察者与业务命令调度思路 | 不能把Native指针跨进程直传或异步长期保存 |

优先方式：C++既有模块保留现用原生库/进程，另在x3定义**稳定C#契约**，通过C ABI/IPC做Adapter。若新功能纯.NET更简洁，也可按同语义实现但必须做协议回归；不引入旧`CxApplication`进WPF消息泵。

## 4. 明确发现的风险与证据等级

| 编号/级别 | 源码位置 | 观察与判断 | 处理 |
|---|---|---|---|
| EVT-01 / 高 | [`cxchannel.h#L166`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxchannel.h#L166) | `CxChannelPublisher::removeObserver`仅`std::remove(begin,end,p)`，未见随后的vector `erase`；**从源码即可推导逻辑长度不变**，取消订阅并未真正缩短容器（可重复/悬挂观察者）。是否触发现网故障待验证。 | 最小复现，审查生产依赖后修复或在Adapter屏蔽 |
| EVT-02 / 高 | [`cxapplication.cpp#L244-L285`](https://github.com/oudream/ccxx/blob/26cecfb02e861ce6b821b33350493bac4793e997/ccxx/cxapplication.cpp#L244-L285) | 满回调环调用`CxApplication::exit()`；单事件数据`>=4MiB`被拒收。队列也不提供调用方明确的Backpressure结果。 | 队列容量/拥塞、丢弃策略、明确错误返回、百万事件压力 |

## 5. 可执行验收任务

1. 构建`test/channel/` TCP client/server、UDP、serial模拟回环及`test/application/`、`test/timer/`；分别Windows x64/Linux明确环境、命令与输出。
2. 统一连接状态机用例：未启动→Open→Connected→发送/接收→断链→重连→Close→析构；同时覆盖重复Close、半包/粘包、异常远端。
3. 注册、移除、再次注册Observer；用AddressSanitizer/UBSan（支持的平台）观察悬挂回调；保留生产分支兼容路径。
4. 回调队列0/高并发/超容量/大消息/回调抛异常；输出队列长度、丢失/拒绝量、事件处理延迟及停机结果。
5. 对照`cx-visual-x3/Mechanism/Connectivity`骨架，确定最小的`ChannelDefinition / ChannelSession / ChannelEvent / ChannelHealth`契约（仅候选名），先批准Owner与签名再编码。
