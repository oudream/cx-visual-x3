# CxVisual 统一配置公共底座 · 集中实现与验收基线

## 阶段定位
此阶段不因旧项目、旧配置文件或具体设备而拆分架构。公共配置主体仅为：
- Foundation/Data/Configuration：强类型模型描述、Schema、类型Codec、校验、完整元数据目录/搜索/自动文档
- Mechanism/Data/Configuration：统一服务、作用域与显式层级覆盖、事务、历史、原子文件存储、变更订阅、生效审查、版本化任务快照、可交换配置包

专业程序集日后只定义自己的 POCO、校验器与受控生效适配器，不再建第二个独立配置管理器。

## 基础能力的职责闭环
1. 定义：类型、多层嵌套、默认值、MemberId、Order、分类、单位、说明、校验规则、所需生效边界
2. 查找：组件注册与查询、Schema 目录、字段搜索和自动文档，普通属性窗可以直接消费这些元数据
3. 读取：强类型完整模型、截面、单值，默认/上次保存/最新保存/上一生效/当前有效、历史版本
4. 修改：事务草稿、同步/异步预览、错误报告、稳定差异路径、单值修改、校验后原子提交
5. 历史：独立修订链、旧值查询、受控恢复，提交与生效分离
6. 层级：模板、工程、机台、产品、运行覆盖等通过显式优先级组合，不覆盖未声明的字段，返回来源链和各层版本
7. 运行：单层或整组层级固定任务快照，版本证据，生效边界控制和外部审查拒绝原因，不直接操作设备
8. 通知：单值/截面/整体和层级有效值事件，新旧值、默认、来源与版本，支持退订及异常隔离
9. 交换：离线配置包携带 SectionId、SchemaVersion、来源修订、SHA-256 完整性校验；导入仍走统一验证/提交

## 不把未来集成误写成基础能力已完成
- 设备许可、联锁、读回与实际执行确认：本阶段只实现审查契约，专业/Runtime 负责接入实机；默认无硬件 ACK。
- 跨进程/跨机台同步、可靠重放、数字签名和授权审批：SHA-256 仅能证明传输内容一致，不提供发布真实性或权限。
- Studio 生成表单：Schema 目录已可供 UI 消费，但真实可视化工作台和人工交互验收尚未完成。
- 多层存储的跨文件全局原子生效与发布事务：目前保证每层存储原子更新、读取固定有效版本向量；不能宣称分布式原子切换。
- YAML/INI 原文件格式及注释的无损编辑、复杂旧文件迁移链：暂不阻塞**基础公共 API**的收敛，后续作为具体 Adapter 与兼容性测试。
