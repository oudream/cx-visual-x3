| ChannelKind | 配置类型 | 正式通道类 | 核对证据 | 现阶段边界 |

| TcpClient | MCCTcpClientChannelConfiguration | MCCTcpClientChannel | Windows TCP loopback | 外部设备 HIL 待验 |
| TcpServer | MCCTcpServerChannelConfiguration | MCCTcpServerChannel | TCP MultiPeer / Generation | 多网卡、极限并发待验 |

> HTTP/WebSocket 通道只负责原始字节或消息传输；SOAP/REST/MQTT 在 Protocol 或 Service 层，不应变成新的重复 Channel。

## 2. 配置拆分机制

- 单一 `MCNConnectorConfiguration.Channel` 属性不变；`MCCChannelConfiguration` 改为抽象的公共配置。
- 每一种配置有对应独立 CLR 类型与 `FCMConfigItem` 注解；`MCCChannelConfigurations.TypeOf/Create` 只允许白名单。
- 通过已有 FCM ValueConverter 序列化/反序列化；旧版单对象平铺配置采用受控迁移，遇到未知字段或与通道种类冲突的非默认属性则拒绝。
- `MHSConfigEditorModel` 的设置路径以当前合法运行子类型解析，`MPWConfigEditorDialogV14` 针对 Channel 多态子类型提供字段界面，选择 Kind 后替换整个 Channel 节点，仍使用原有 MHS 存储/Undo。
- `FCMConfigDiffUtil` 子类型切换时按节点整体变更记录，不以新类型的反射属性读取旧类型。
- 所有现场驱动/专属SDK调用仍属于 Driver / Professional，不因“Custom Channel 配置”产生虚假设备能力。

## 3. 尚未完成的通道清单（不得用空类验收）

- HTTP Server、WebSocket Server：多客户端/会话、真实请求响应、超时取消、ACL/TLS 与 Windows Socket 验收。
- File Channel：文件输入输出或目录监听、原子交接、损坏文件隔离、数据预算；Replay 已独立完成，不等于 File 收发完整实现。
- SharedMemory（SHM）：跨进程 MMF、明确所有权/版本/校验、进程异常释放及大体积压力测试；不允许直接传播跨进程裸指针。
- CAN / 工业总线：需要明确硬件驱动、帧边界及厂商 SDK 的真实依赖；无实机和 SDK 不以 Demo/适配器冒充生产实现。
- 原生 IPC Socket、USB 及其他专业设备：需确认 .NET48/Windows 硬件能力和正式 Owner，必要时归 Driver，而不是重新造 SDK。
- InMemory/Loopback 已有 `MCCVirtualChannel.CreatePair`，不为更换名字重复实现同义 Channel。
- MQTT 只作为上层 Protocol，不新增独立 MQTT Socket Channel。
