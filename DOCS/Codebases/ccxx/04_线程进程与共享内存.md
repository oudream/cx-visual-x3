## 2. 未来CxVisual通信边界（**设计建议，不是声称已有实现**）

~~~
CxVisual.Runtime.Host (.NET)
  -> C ABI / IPC Adapter（统一版本、错误、资源所有权）
     -> Native Worker（ccxx或cx-cct-x3）
        -> 命名SHM/字节缓冲承载大块数据
        -> Worker处理并返回状态、日志与结果
~~~

建议定义message-header：magic/version/size/requestId/status/error；引用数据采用shm-name/offset/length/stride/type。明确创建者、读取者、释放者、跨进程锁/序列号、恢复超时、崩溃回收。**ccxx目前只提供底层映射操作，不能因此声称拥有cx-cct-x3那套完整任务协议。**

## 4. CxVisual唯一Owner建议

- Foundation.Infrastructure：线程、时间、诊断与系统环境基本契约；新C#层不必重新实现OS线程原语。
- Foundation.Transport：传输缓冲与SHM底层数据约定；需要按F17规格再定唯一Owner。
- Mechanism.Runtime / Runtime.Host：Native工作者编排、任务超时、启动重启、会话与健康状态。
- Mechanism.Lifecycle：版本和发布、Worker/IPC兼容升级。
- Professional.CT3D/Vision/Automation：专业设备、重建、采集及高性能算法应用；不得上移专业领域实体。

C#与C++间禁止直接暴露std::string/std::vector/C++实例裸指针作为长期稳定ABI。共享内存坐标、体素格式和内存所有权还须与cx-cct-x3的module_api/shm_api逐项对照。

## 5. 跨平台测试矩阵（未执行）

1. Windows x64（MSVC）/Linux（GCC/Clang）分别构建相关ccxx目标，记录依赖和构建配置。
2. NamedShm：create/view/read/write/len/offset/close/remove；无权限、重复名、匿名fallback、越界、写进程崩溃。
3. Thread：启动/关闭/join、取消、资源回收、反复10000次、异常线程退出和wait超时。
4. Process：有效/不存在的命令、参数空格、execve失败状态、启动后kill/wait、Detached行为。
5. IPC集成：跨语言结构体对齐、字节序、版本、进程退出后的回收、GB级数据和资源长期泄漏。
6. 原生库改动要先做兼容影响评估，旧系统受影响前先验证原部署分支、修复测试后再实施。
